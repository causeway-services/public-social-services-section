## Research and video publishing

Run from this directory using the repository's package resolver:

```sh
node --import ../../../../../engineering-services-section/services/computer-engineering-services-section/services/computer-code-engineering-services-section/services/javascript-engineering-services-section/services/javascript-node-services-section/scripts/register-house-resolver.mjs src/cli.mjs status all
```

The same entrypoint accepts `research <channel> <lesson>` to prepare a report without requesting a video; `produce [channel|all] [lesson]` fills upcoming publication slots or advances the named lesson; `artifacts <channel>` lists notebook videos; `adopt <channel> <lesson> <artifact-id>` reconciles an uncertain submission; `retry <channel> <lesson>` readmits a failed or abandoned video; and `verify [channel|all]` checks configured YouTube identities. A channel connects through its account holder: a channel whose refresh token the node does not hold is an obligation (`src/obligations.mjs`) on the character in the profile's `obligationSources`, and signing in to the operations console walks them through Google's consent at `/obligations`. On a machine with a browser, `node --import <resolver> src/authorize.mjs <channel>` connects one directly.

To offer observed, expiring account capacity for thumbnails, set `INFERENCE_ACCOUNT_ENTITLEMENTS_FILE` to a local JSON file with an `observations` array. Each observation must record `type: "AccountArtifactEntitlementObservation"`, opaque `accountIdentity`, `providerIdentity`, `product`, `windowIdentity`, `resourceUnit`, `capabilities: ["image-generation"]`, `executionMode: "operator-mediated"`, `zeroCash: true`, `observedAt`, `validUntil`, `expiresAt`, integer `remaining` and `unitsPerArtifact`, and `provenance: {"kind":"operator-ui","reference":"..."}`. Record only capacity and cost actually visible in the account UI; no account credentials belong in this file. `inspect_inference_resources` shows these observations separately from API providers.

When a current observation can serve a lesson thumbnail, `produce` holds its observed credits in a shared SQLite capacity store and writes an operator packet to the channel's ignored `.work/<lesson>/thumbnail-work.json`. The store defaults to `<INFERENCE_ACCOUNT_ENTITLEMENTS_FILE>.reservations.sqlite`; set `INFERENCE_ACCOUNT_CAPACITY_FILE` when several consumers need one explicit shared location. Review the packet and run `begin-thumbnail <channel> <lesson>` before using the named account UI. Complete the packet there, then run `adopt-thumbnail <channel> <lesson> <downloaded-image> <spent-units>` through the same CLI. Adoption checks the source hashes, records the returned image hash and operator-reported spend in `production/episodes/<lesson>/thumbnail-receipt.json`, fits the publication JPEG, settles the held credits, and lets the next `produce` run continue. A fresh UI observation for the same account window can replace the accounting baseline while unresolved holds remain reserved. If the product refused or the packet expired without an artifact, update the observation and run `release-thumbnail <channel> <lesson> <expired|logged-out|quota-exhausted|ui-changed|operator-declined>` before retrying. An unstarted hold is released; an attempted packet keeps its full quoted charge when actual spend is unknown. The released packet is retained for reconciliation. Without a current observation, the existing image generator continues automatically. Both routes retain the source and prompt in `production/episodes/<lesson>/thumbnail-work.json` and the output hash in `thumbnail-receipt.json`.

Production automatically selects unpublished curriculum lessons to keep at least two upcoming videos per enabled channel, counting work already in progress, and commissions more when Gemini Notebook capacity would otherwise lapse. Each `produce` reads every enabled channel's queue and divides the next `capacity.lookaheadWindows` usage windows of each Gemini Notebook allowance (`production.json`; see the Gemini Notebook package's account usage windows) among the channels whose format draws on it, each format priced at the estimate of what the allowance has learned (admission itself stays with the ledger's sure reading), least served over the last `capacity.fairnessDays` first and never past `capacity.horizonDays` of publication slots. It prints the plan: `idleUnits` that no channel can take, `lapsed` capacity each allowance lost over the fairness horizon, allowances with no consumer at all, and the kinds of an allowance (infographics, slide decks) that no channel makes (`unconsumed`). A lesson holds its video's kind in the inference engine's allowance ledger just before submission (state `videoHold`). It waits as `awaiting-capacity` when the window does not fit it, or probes, one lesson at a time, where the budget is not yet known. A bound artifact is recorded as a spend under its Studio source. A fresh quota refusal is recorded as a refusal the allowance learns from. A refusal before acceptance spends no capacity; a request accepted by Notebook remains spent even if the artifact later fails. A video the provider confirms failed is tried again by `videoRetry` in `production.json`: the channel's format up to `preferredFormatAttempts` times, then each `fallbackFormats` entry once. A lesson whose formats are all spent is abandoned: it stops counting toward the two upcoming videos, the next lesson takes its slot, and `retry` readmits it. The command exits nonzero only for a fault in the program or its retained data, not for a lesson that is waiting. It uses publication history and live YouTube inventory to avoid repeating videos. When the curriculum is exhausted, it appends distinct lesson questions based on the course and existing topics. `produceVideo: true` remains an explicit commissioning option. Research produces Markdown reports and adjacent source/search evidence in the curriculum. Each Notebook video retains `production/episodes/<lesson>/video-work.json` with the exact source and prompt, then `video-work-receipt.json` with the downloaded output hash and provider artifact ID. The inference engine owns report drafting and admission; Gemini Notebook owns recoverable report-to-video production; media engineering owns raster fitting and audio extraction. This education workflow supplies curriculum prompts, channel artwork direction, publication slots, and the composition of those capabilities with transcription and YouTube publishing. Reports can also feed articles and books.

Existing channel `production/episodes/<lesson>/state.json` and `record.jsonl` retain progress and provenance. Downloads and resumable upload URLs stay in each channel's ignored `.work/` directory. A submitted report cannot be silently replaced; uncertain video submissions retain their exact checkpoint until their provider outcome can be reconciled. YouTube credentials (the shared OAuth client and each channel's refresh token) live in the node's one YouTube credential home, `~/.config/561-group/youtube.env` (see the YouTube engineering section); other credentials load from this directory's `.env` and ancestor `.env` files. Neither overrides the process environment. `scripts/transfer-auth-profile.mjs restore|save notebook|codex` carries the local Gemini Notebook or Codex profile through `NOTEBOOKLM_AUTH_JSON` or `CODEX_AUTH_JSON`; encrypted snapshots live in this package's `state/` directory. The education wrapper keeps the legacy `youtube-notebook` and `youtube-codex` encryption namespaces so existing snapshots remain readable.

Cold Red Gate runs production independently of the founder's laptop. Its persistent user timers `media-production-education`, `media-production-flow`, and `media-production-publish` advance work every twenty minutes after each run finishes. Education and Flow share a server-side lock and capacity ledger; publishing also runs when a generation run ends. The laptop production jobs have been removed.

The server owns the active curricula, reports and publication checkpoints at `~/.local/state/561-group/education`, the Flow queue at `~/.local/state/561-group/google-flow`, and their allowance ledger at `~/.local/state/561-group/media-allowance-ledger.sqlite`. Provider credentials stay in private server files. Drive is the retained media hub: every new artifact is transferred immediately to `gdrive:561 Group/Media/education/<channel>/<lesson>` or `gdrive:561 Group/Media/flow/<consumer>` under its SHA-256 filename. A Drive receipt records the file ID, link, byte count, SHA-256 and remotely verified MD5. The VPS retains only active working copies and removes completed cache files after verified custody. Retries materialize the original bytes from Drive. Reports and publication records are also copied to Drive; resumable upload credentials are excluded.

Both Gemini Notebook briefs and Google Flow scenes become YouTube Shorts, with separate upload identities and the same lesson's exact longform video as their hub. Notebook briefs vary between worked examples, misconceptions, mechanisms and tradeoffs. The complete brief is retained in Drive and fitted into a square carrier without cropping diagrams. Flow prompts are constructed from the report with a distinct teaching angle and a verbatim, readable lesson claim; the exact caption is added to a vertical carrier afterward. Existing Flow artifacts can be received from Drive without another generation. ffprobe checks both carriers against YouTube's three-minute limit. Source media and finished Shorts enter Drive before YouTube upload. Titles contain two to four specific topic hashtags. `notebook-short.json` and `flow-short-<hash>.json` retain each provider's progress independently, so a quota refusal or authentication wait cannot suppress the other provider.

Studio's native Related Video selection is saved and checked after reload; description links supplement it. The parent must be public or unlisted. A new Short stays private until processing and native linkage succeed. Google may require human verification on the server before Studio saves; the checkpoint records pending authentication rather than claiming a linked publication. Video-management OAuth consent is also required for changing existing titles and publishing private uploads. `shorts <channel|all> [lesson]` advances both providers explicitly; normal production also advances them before optional companions. The original Flow Shorts are repaired in place with their existing upload IDs and longform parents. Flow remains available for other footage and thumbnails.

From any SSH client, `ssh cold-red-gate '~/.nvm/versions/node/v24.16.0/bin/node ~/.local/share/561-group/media-production/current/media-production.mjs status'` shows active education work; replace `status` with `verify` to check YouTube identities. Submit a JSON Flow order to that entrypoint's `queue` command on stdin. `systemctl --user start media-production@education` or `media-production@flow` starts a server run immediately, and `journalctl --user -u media-production@education` (or `@flow`, `@publish`) shows its results. This continues after SSH disconnects and across reboots; user lingering is enabled.

The deployment source and code-only installer live in the operations deployment's `cold-red-gate-host/deploy/` directory (`install-media-production.py`). The installer retains a private hard-linked snapshot of the server's shared runtime, so cleanup by another deployment cannot delete media dependencies. Updated media, inference and allowance code is installed together. Server-owned sources, state and credentials remain intact. This requires the server's Notebook Python runtime, Playwright Chromium, ffmpeg/ffprobe, rclone `gdrive` remote, and provider logins. `scripts/checkpoint.mjs` remains available for manually retaining a source checkout's production in Git; hosted production retains its own checkpoints and outputs in Drive.
