## Research and video publishing

Run from this directory using the repository's package resolver:

```sh
node --import ../../../../../engineering-services-section/services/computer-engineering-services-section/services/computer-code-engineering-services-section/services/javascript-engineering-services-section/services/javascript-node-services-section/scripts/register-house-resolver.mjs src/cli.mjs status all
```

The same entrypoint accepts `research <channel> <lesson>` to prepare a report without requesting a video; `produce [channel|all] [lesson]` fills upcoming publication slots or advances the named lesson; `artifacts <channel>` lists notebook videos; `adopt <channel> <lesson> <artifact-id>` reconciles an uncertain submission; `retry <channel> <lesson>` readmits a failed or abandoned video; and `verify [channel|all]` checks configured YouTube identities. `node --import <resolver> src/authorize.mjs <channel>` connects an account.

To offer observed, expiring account capacity for thumbnails, set `INFERENCE_ACCOUNT_ENTITLEMENTS_FILE` to a local JSON file with an `observations` array. Each observation must record `type: "AccountArtifactEntitlementObservation"`, opaque `accountIdentity`, `providerIdentity`, `product`, `windowIdentity`, `resourceUnit`, `capabilities: ["image-generation"]`, `executionMode: "operator-mediated"`, `zeroCash: true`, `observedAt`, `validUntil`, `expiresAt`, integer `remaining` and `unitsPerArtifact`, and `provenance: {"kind":"operator-ui","reference":"..."}`. Record only capacity and cost actually visible in the account UI; no account credentials belong in this file. `inspect_inference_resources` shows these observations separately from API providers.

When a current observation can serve a lesson thumbnail, `produce` holds its observed credits in a shared SQLite capacity store and writes an operator packet to the channel's ignored `.work/<lesson>/thumbnail-work.json`. The store defaults to `<INFERENCE_ACCOUNT_ENTITLEMENTS_FILE>.reservations.sqlite`; set `INFERENCE_ACCOUNT_CAPACITY_FILE` when several consumers need one explicit shared location. Review the packet and run `begin-thumbnail <channel> <lesson>` before using the named account UI. Complete the packet there, then run `adopt-thumbnail <channel> <lesson> <downloaded-image> <spent-units>` through the same CLI. Adoption checks the source hashes, records the returned image hash and operator-reported spend in `production/episodes/<lesson>/thumbnail-receipt.json`, fits the publication JPEG, settles the held credits, and lets the next `produce` run continue. A fresh UI observation for the same account window can replace the accounting baseline while unresolved holds remain reserved. If the product refused or the packet expired without an artifact, update the observation and run `release-thumbnail <channel> <lesson> <expired|logged-out|quota-exhausted|ui-changed|operator-declined>` before retrying. An unstarted hold is released; an attempted packet keeps its full quoted charge when actual spend is unknown. The released packet is retained for reconciliation. Without a current observation, the existing image generator continues automatically. Both routes retain the source and prompt in `production/episodes/<lesson>/thumbnail-work.json` and the output hash in `thumbnail-receipt.json`.

Production automatically selects unpublished curriculum lessons to keep at least two upcoming videos per enabled channel, counting work already in progress, and commissions more when Gemini Notebook capacity would otherwise lapse. Each `produce` reads every enabled channel's queue and divides the next `capacity.lookaheadWindows` usage windows of each Gemini Notebook allowance (`production.json`; see the Gemini Notebook package's account usage windows) among the channels whose format draws on it, each format priced at the estimate of what the allowance has learned (admission itself stays with the ledger's sure reading), least served over the last `capacity.fairnessDays` first and never past `capacity.horizonDays` of publication slots. It prints the plan: `idleUnits` that no channel can take, `lapsed` capacity each allowance lost over the fairness horizon, allowances with no consumer at all, and the kinds of an allowance (infographics, slide decks) that no channel makes (`unconsumed`). A lesson holds its video's kind in the inference engine's allowance ledger just before submission (state `videoHold`). It waits as `awaiting-capacity` when the window does not fit it, or probes, one lesson at a time, where the budget is not yet known. A bound artifact is recorded as a spend under its Studio source. A fresh quota refusal is recorded as a refusal the allowance learns from. A confirmed failure for another reason spends nothing. A video the provider confirms failed is tried again by `videoRetry` in `production.json`: the channel's format up to `preferredFormatAttempts` times, then each `fallbackFormats` entry once. A lesson whose formats are all spent is abandoned: it stops counting toward the two upcoming videos, the next lesson takes its slot, and `retry` readmits it. The command exits nonzero only for a fault in the program or its retained data, not for a lesson that is waiting. It uses publication history and live YouTube inventory to avoid repeating videos. When the curriculum is exhausted, it appends distinct lesson questions based on the course and existing topics. `produceVideo: true` remains an explicit commissioning option. Research produces Markdown reports and adjacent source/search evidence in the curriculum. Each Notebook video retains `production/episodes/<lesson>/video-work.json` with the exact source and prompt, then `video-work-receipt.json` with the downloaded output hash and provider artifact ID. The inference engine owns report drafting and admission; Gemini Notebook owns recoverable report-to-video production; media engineering owns raster fitting and audio extraction. This education workflow supplies curriculum prompts, channel artwork direction, publication slots, and the composition of those capabilities with transcription and YouTube publishing. Reports can also feed articles and books.

Existing channel `production/episodes/<lesson>/state.json` and `record.jsonl` retain progress and provenance. Downloads and resumable upload URLs stay in each channel's ignored `.work/` directory. A submitted report cannot be silently replaced; uncertain video submissions retain their exact checkpoint until their provider outcome can be reconciled. Credentials load from this directory's `.env` and ancestor `.env` files without overriding the process environment. `scripts/transfer-auth-profile.mjs restore|save notebook|codex` carries the local Gemini Notebook or Codex profile through `NOTEBOOKLM_AUTH_JSON` or `CODEX_AUTH_JSON`; encrypted snapshots live in this package's `state/` directory. The education wrapper keeps the legacy `youtube-notebook` and `youtube-codex` encryption namespaces so existing snapshots remain readable.

The local `content/systemd/youtube-production.timer` runs production every twenty minutes; its service then runs `scripts/checkpoint.mjs` to retain production state, reports, and curriculum additions in Git. Link both units with `systemctl --user link` and enable the timer. The obsolete GitHub workflow that invoked removed production commands has been retired; production runs on the host with the provider logins. Install Gemini Notebook through its provider package and make ffmpeg/ffprobe available on PATH.
